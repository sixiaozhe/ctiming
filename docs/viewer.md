# ctiming HTML 查看器

`ctiming-analyze` 可以把分析结果生成为**自包含、离线可用**的单文件 HTML 报告：报告内含分析数据与查看器（CSS/JS 全部内联），不引用任何 CDN 或外部资源，直接用浏览器打开即可，无需网络、无需服务端。它属于**计划 3**，读取计划 2 生成的 `analysis.json` 数据。

## 生成方式

```bash
./build/example_single
./build/ctiming-analyze example_single.ctrace -o report.html
```

- `-o FILE` 与 `--html FILE` **等价**，指定 HTML 报告输出路径。
- `-o`/`--html` 可与 `--json FILE` **同时使用**：一次运行同时写出 HTML 报告与全量 `analysis.json`。
- 给出 `-o`/`--html`（和/或 `--json`）后不再打印文本摘要；写出成功时打印一行 `wrote FILE`，写出失败退出码为 `1`。两者都未给出时仍打印文本摘要。
- `--include` / `--exclude` / `--min-total` / `--top` 只影响文本摘要与每个函数的 `kept` 标记，**不会缩减**内嵌到报告里的数据；报告始终包含全量、自洽的数据。

报告是一个普通 `.html` 文件，可以随意拷贝、归档、发邮件或放到静态服务器上，打开后功能完整。

## 界面结构

页头显示被追踪程序路径与采集概况（线程数、事件数，若有截断则附 `dropped`）。下方是 Tab 栏，共五个视图：**概览、火焰图、调用关系图、单次追踪、调用者/被调用者**。所有耗时按量级自适应格式化为 `ns` / `µs` / `ms` / `s`。

### 概览

- 顶部 KPI 卡片：最重函数总耗时、事件数、线程数、有调用的函数数、截断/丢弃、未配对 ENTER。
- 热点表按总耗时降序排列，列为：函数、调用次数、自身耗时、总耗时、最慢一次、占比（相对最重函数）。
- 点击“调用次数”“自身耗时”“总耗时”表头可切换排序维度。
- 点击任意一行会跳到**调用者/被调用者**页并选中该函数。
- 为控制渲染量，表格最多显示前 200 个函数；更精确的定位请用“调用者/被调用者”页的搜索。

### 火焰图

- 展示聚合调用树（`aggregated`），每个矩形**宽度 = 累计耗时**（`total_ns`），同一层按耗时占比横向铺开。
- 矩形颜色按节点占当前视图总耗时的比例由冷到热。
- 点击**有子节点**的矩形下钻到该子树；顶部面包屑显示“全部 / 祖先 / …”，点击任一层可回退。
- 点击**叶子**矩形（无子节点）会跳到**调用者/被调用者**页。
- “自底向上”按钮把视图上下翻转（叶子在上、根在下），便于观察自底向上的聚合；该按钮只做**视觉翻转**，不改变调用树本身。
- 鼠标悬停任一矩形显示函数名、总耗时、自身耗时与调用次数。

### 调用关系图

- 取总耗时最高的前 40 个函数（只含 `calls > 0`），按环形布局放置节点。
- 有向边表示调用；**线宽 = 调用次数**（相对图中最大次数缩放），悬停显示调用方、被调用方、次数与总耗时。
- **红色边表示递归**（对应 `call_graph` 的 `recursive` 标记）。
- 节点颜色：通过文本摘要过滤（`kept`）的函数为强调色，其余为灰色。
- 点击节点跳到**调用者/被调用者**页查看其上下游；图中只画两端都在这 40 个函数内的边。

### 单次追踪

- 左侧列出所有线程的**顶层调用实例**（`threads[].roots`），按单次时长降序。
- 顶部搜索框按函数名过滤顶层调用；无匹配时右侧清空。
- 右侧是被选中实例的**整棵子树瀑布图**：横轴为该实例的时间跨度，条形按调用深度缩进，并按深度配色（根为红，向下依次暖/冷色）。
- 标题行显示函数名、时长、`tid` 与直接子调用数；悬停条形显示该次调用的时长与自身耗时。

### 调用者/被调用者

- 搜索框输入函数名，下方给出候选列表（最多 30 个，只含 `calls > 0`）；点击候选即选中。
- 选中函数后顶部显示其 KPI：调用次数、自身耗时、总耗时、最慢一次。
- 下方两张表：
  - **调用者（谁调用了它）**：对应入边，列为调用者、次数、总耗时、是否递归；线程入口等无调用者时提示“无”。
  - **被调用者（它调用了谁）**：对应出边，列为被调用者、次数、总耗时、是否递归；叶子函数提示“无”。
- 两张表都按边的总耗时降序；点击表中函数名可跳转继续查看。

## 数据来源

报告生成时，查看器把 `analysis.json` 的内容原样内嵌到页面中的 `<script id="ct-data" type="application/json">…</script>`，查看器在浏览器启动时读取并 `JSON.parse` 该脚本；内嵌文本中的 `<`/`>` 会被转义为 `\u003c`/`\u003e`，避免提前闭合脚本标签，但仍是合法 JSON。所有视图完全由这份内嵌数据渲染，不发起任何网络请求。

字段语义、`total_ns`/`self_ns`/`call_graph`/`instances` 等定义以及过滤与 `kept` 的规则，详见 [analyzer.md](analyzer.md)。同时用 `--json` 写出的文件与报告内嵌的数据同源同内容。

## 已知限制

- **实例全量内嵌**：`instances`（每次进入/退出的具体调用）会整体写入 HTML，超大 trace 会使报告文件明显变大，打开也会更慢。如需控制体积，应先用运行时的 `CTIMING_*` 过滤或分析器的过滤参数减少事件量。
- **仅在浏览器端运行**：所有渲染由内联 JS 完成，没有服务端，也没有数据下载/查询接口；数据在生成报告时即已固化。
- **火焰图“自底向上”是视觉翻转**，并非真正的反向聚合，下钻路径仍以聚合树为准。
- **调用关系图只取总耗时前 40 个函数**，更多函数请用“概览”或“调用者/被调用者”定位。
- **概览表最多显示前 200 个函数**。
