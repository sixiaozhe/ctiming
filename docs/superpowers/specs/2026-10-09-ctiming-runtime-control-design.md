# ctiming 运行期控制与子树追踪 设计

- 日期：2026-10-09
- 状态：已定稿，待实现
- 关联：`docs/superpowers/specs/2026-09-30-ctiming-design.md`

## 1. 目标

在程序运行过程中由人工主动控制记录（开关、导出、设置追踪目标），并支持“只追踪指定符号及其以下的调用栈”（子树追踪）。

## 2. 控制通道（FIFO）

- 环境变量 `CTIMING_CTL=<path>`。设置后，运行时启动时 `mkfifo`（不存在则创建，0600），并起后台线程以 `O_RDWR` 打开、逐行读取命令。
- 命令（一行一条，首 token 为命令名，其余为参数）：
  - `start` / `stop` / `toggle`：记录总开关（等价 `ctiming_start/stop`）。
  - `dump [PATH]`：立即导出当前缓冲到 PATH（缺省 `CTIMING_OUT`）。
  - `trace <模式>`：设置子树追踪根（逗号分隔 glob，可匹配多个函数）；`trace off` / `untrace` 清除。
  - `include <glob…>` / `exclude <glob…>`：运行期改名称过滤（空清除）。
  - `status`：打印当前状态。
  - 未知命令打印提示。
- 反馈信息打到 stderr。

## 3. 子树追踪语义

- 设置追踪根 F 后：**只记录处于 F 动态范围内（含 F 本身）的调用**，F 之外不记录；天然形成以 F 为根的调用树。
- 匹配按**地址**：设置时扫描运行期符号表，把名字匹配的函数入口地址存入不可变快照；钩子内仅做二分查找。
- 每线程独立：某线程调用 F 则捕获该线程的这棵子树；多线程/多次调用各自成树。
- 递归：进入最外层 F 时开启，直到该层 F 返回关闭（`depth == 捕获起始深度`）。

## 4. 与现有过滤的关系

- 未设置追踪根：行为不变（`INCLUDE`/`EXCLUDE` + 默认标准库排除 + `DROP_UNKNOWN`）。
- 设置追踪根：子树内**忽略 `INCLUDE`**（保证子树完整），仍遵守 `EXCLUDE` 与默认标准库排除。

## 5. 设置时机与 API

- 启动期：`CTIMING_TRACE=<glob>` → 初始化后立即生效。
- 运行期：FIFO 的 `trace/trace off/include/exclude`。
- 公共 API：`int ctiming_set_trace_symbol(const char *pattern);` 返回命中地址数（0 表示未命中或清除）。

## 6. 影响

- `.ctrace` 格式不变；分析器/查看器无需改动（子树成为以 F 为根的调用树）。

## 7. 已知限制

- `dump` 只导出已退役线程缓冲 + 调用 `dump` 线程自身的缓冲（与现有实现一致）。
- FIFO 命令线程启动发生在首次插桩调用触发的初始化中。
- 追踪根在设置时刻解析地址；之后新加载的模块（dlopen）不在匹配范围内。
